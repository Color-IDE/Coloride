# LOT-021 — Modes *Créer* (Catalogue Visuel AST) & *Apprendre* (Micro-Agent Pédagogique)

**Domaine :** Personas & Adaptation UX/UI (Phase 2 — Bêta Fermée)
**Module :** `apps/web-ui`, `crates/host-core`, `crates/judge-orchestrator`
**Jalon :** `M2.0 - Closed Beta (8-Chat Grid)`
**Priorité :** P1
**Complexité :** Moyenne
**Estimation :** 4 jours (32 h)
**Dépendances :** [LOT-015](./LOT-015.md), [LOT-016](./LOT-016.md), [LOT-018](./LOT-018.md)
**Parallélisable avec :** [LOT-019](./LOT-019.md), [LOT-020](./LOT-020.md), [LOT-022](./LOT-022.md)

---

### 4.1 Objectif
Livrer les adaptations UX/architecturales des personas **Grand public / No-Code** (mode **Créer** : templates React, catalogue de composants à identifiants stables et sélection visuelle traduite en modifications AST sur le code) et **Développeur débutant** (mode **Apprendre** : micro-agent pédagogique contextualisant diagnostics, diffs et coûts avant application).

### 4.2 Périmètre
- **IN :**
  - **Mode *Créer* (Persona Grand public / No-Code) :** templates React initiaux et catalogue de composants certifiés ; sélection visuelle d'un composant dans le `Preview Service` via identifiants stables (`data-coloride-id`) ; panneau d'édition visuelle (texte, variantes, styles, props) traduit directement par `AstChangeSetCompiler` en modifications de code TypeScript/React ; affichage clair du coût et de l'historique compréhensible ; maintien de la règle : un composant arbitraire non reconnu reste visible dans l'aperçu et éditable en code.
  - **Mode *Apprendre* (Persona Développeur débutant) :** micro-agent pédagogique recevant le diagnostic (`vtsls`/Biome), le code pertinent et le résultat des tests pour expliquer la cause d'une erreur et le fonctionnement d'une correction avant son application ; affichage progressif guidé du diff, du terminal et du debugger.
  - Respect des invariants d'adaptation progressive : choix explicite du profil par workspace, aucune disparition automatique de panneau en cours de tâche, arborescence toujours disponible, permissions du `Policy Engine` strictement identiques quel que soit le mode.
- **OUT :**
  - Conversion visuelle universelle de code impératif arbitraire hors catalogue (explicitement non promise par l'architecture).

### 4.3 Prérequis
- [LOT-015](./LOT-015.md), [LOT-016](./LOT-016.md), [LOT-018](./LOT-018.md).

### 4.4 Implémentation
1. Ajouter dans le plugin de dev du `Preview Service` l'annotation automatique des éléments JSX avec leur identifiant de nœud AST (`file_path + symbol + byte_offset_hash`).
2. Implémenter `VisualAstMutator` dans `crates/host-core` : lorsqu'un utilisateur en mode *Créer* modifie une propriété dans l'inspecteur visuel, générer une `EditorTransaction` / `ChangeSet` AST exacte, formatée par Biome et validée par le Juge.
3. Implémenter `PedagogicalAgentService` dans `crates/judge-orchestrator` : génère des explications structurées (« Pourquoi cette erreur ? », « Ce que fait le correctif ligne par ligne », « Impact et coût ») rattachées aux diagnostics et aux zones `🟡` / `🔴`.

### 4.5 Tests obligatoires
- **Test de cohérence bidirectionnelle Mode *Créer* ↔ Mode *Développer* (Bloquant) :**
  - *Scénario :* Créer une page à partir d'un template React en mode *Créer*, modifier 3 composants visuellement, basculer en mode *Développer* pour ajouter un composant personnalisé complexe avec hooks en code dans CodeMirror 6, puis revenir en mode *Créer*.
  - *Résultat attendu :* Le code source `.tsx` est propre, valide (`🟢`) et demeure l'unique source de vérité ; les composants du catalogue restent éditables visuellement et le composant personnalisé reste intact, visible dans l'aperçu et éditable en code.
- **Test d'invariance des permissions de sécurité entre Personas (Bloquant) :**
  - *Scénario :* Soumettre le même `ToolCall` non autorisé en mode *Créer*, en mode *Apprendre* et en mode *Développer*.
  - *Résultat attendu :* Refus strictement identique par le `Policy Engine` dans les 3 modes.

### 4.6 Critères d'acceptation
- [ ] Toute modification visuelle en mode *Créer* produit un diff AST propre et vérifiable sur le code React.
- [ ] En mode *Apprendre*, chaque diagnostic ou patch `🟡`/`🔴` est accompagné d'une explication contextualisée avant application.
- [ ] Aucun panneau ne disparaît automatiquement pendant une tâche et l'arborescence reste accessible à tout moment.

### 4.7 Definition of Done
- Modes *Créer* et *Apprendre*, catalogue de composants AST et micro-agent pédagogique livrés et validés.

### 4.8 Risques et rollback
- **Risques :** Écrasement d'une expression JSX dynamique (`prop={computeValue()}`) par une valeur statique depuis l'éditeur visuel.
- **Mitigation :** Si la valeur d'une prop dans l'AST est une expression dynamique complexe et non un littéral, afficher un cadenas « Expression dynamique (cliquer pour éditer dans le code) » dans l'inspecteur visuel.
