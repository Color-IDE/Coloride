# LOT-017 — API Cloud Managée (Axum/Postgres/OIDC), Runner Fargate & Publication R2/Pages

**Domaine :** Services Cloud, Exécution Managée & Publication
**Module :** Service Cloud (`Rust/Axum`), `crates/sandbox-runner` (Fargate), `crates/host-core` (`PublishService`)
**Jalon :** `M1.4 - MVP Launch Ready`
**Priorité :** P1
**Complexité :** Moyenne
**Estimation :** 4,5 jours (36 h)
**Dépendances :** [LOT-012](./LOT-012.md), [LOT-014](./LOT-014.md), [LOT-016](./LOT-016.md)
**Parallélisable avec :** Préparation de [LOT-018](./LOT-018.md)

---

### 4.1 Objectif
Fournir l'infrastructure cloud managée du MVP : API **Rust/Axum** (REST/OpenAPI, SSE avec reconnexion par curseur, WebSocket terminal), stockage **PostgreSQL + KMS**, identité **OIDC + PKCE** (requise uniquement pour les services managés), exécution sandbox cloud par tâche sur **AWS ECS Fargate** (région UE) et publication statique en 1 clic sur **Cloudflare R2 + Cloudflare Pages/Workers** avec restauration instantanée par digest.

### 4.2 Périmètre
- **IN :**
  - API Cloud `Rust/Axum` exposant des contrats OpenAPI typés, un flux SSE d'événements de tâche paginé par curseur (`cursor_id` / `Last-Event-ID`) et des WebSockets isolés pour les terminaux distants.
  - Persistance PostgreSQL transactionnelle des tâches et stockage d'artefacts identifiés par digest (SHA-256/`blake3`) et isolés par tenant sur stockage objet compatible S3 / Cloudflare R2 + chiffrement KMS.
  - Authentification **OIDC Authorization Code + PKCE** (aucun compte requis pour l'usage local ; l'activation du cloud n'entraîne jamais la synchronisation automatique de tous les dépôts locaux).
  - **Runner Cloud MVP (`FargateSandboxRunner`) :** une tâche AWS ECS Fargate (région UE) par exécution, sans partage inter-tenant, sans mode privilégié ni Docker-in-Docker, secrets LLM conservés dans le broker hors de l'environnement de build, aucun rôle IAM de déploiement accessible au code généré.
  - **Bouton Publier (MVP) :** promotion d'artefacts statiques React/Vite testés (`🟢 ✓ Validé`) vers **Cloudflare R2 + Cloudflare Pages/Workers** (0 $ d'*egress*, invalidation globale `< 50 ms`) ou connecteur externe (Vercel, GitHub Pages), avec restauration en 1 clic vers toute version antérieure identifiée par digest.
- **OUT :**
  - SSR, API serveur hébergée et secrets dans le bundle (explicitement exclus du parcours de publication MVP).

### 4.3 Prérequis
- [LOT-012](./LOT-012.md), [LOT-014](./LOT-014.md), [LOT-016](./LOT-016.md).

### 4.4 Implémentation
1. Implémenter le backend `Axum` avec middleware d'isolation par `tenant_id`, reconnexion SSE par curseur et intégration KMS pour les secrets côté serveur.
2. Implémenter `FargateSandboxRunner` lançant une tâche Fargate éphémère avec une image TypeScript pré-positionnée et détruisant la tâche dès la fin de l'exécution.
3. Implémenter `StaticPublishService` :
   - Vérifie que le snapshot possède un `Evidence` `🟢 ✓ Validé`.
   - Scanne l'intégralité du dossier `dist/` avec `AclAndSecretScanner` ([LOT-008](./LOT-008.md)) pour garantir `0` secret dans le bundle client.
   - Calcule le digest global du bundle, téléverse sur Cloudflare R2 sous une clé adressée par contenu (`artifacts/<tenant>/<digest>/...`) et bascule atomiquement le pointeur de version active sur Cloudflare Pages/Workers.

### 4.5 Tests obligatoires
- **Test de publication puis restauration 1-clic par digest (Bloquant — Scénario bloquant Section 5) :**
  - *Scénario :* Publier la révision `V1` (`digest_1`), vérifier sa disponibilité HTTP, publier `V2` (`digest_2`), tenter de publier un bundle contenant une variable secrète (`SECRET_KEY`), puis déclencher la restauration 1-clic vers `V1`.
  - *Résultat attendu :* Le bundle contenant un secret est bloqué avant publication ; la restauration vers `V1` rétablit `digest_1` en `< 1 s` (invalidation edge `< 50 ms`) avec vérification d'intégrité du digest.
- **Test de reconnexion SSE par curseur et non-synchronisation implicite (Bloquant) :**
  - *Scénario :* Se connecter via OIDC+PKCE, couper le flux SSE à l'événement `#15` pendant que les événements `#16..#20` sont produits, puis reconnecter avec `cursor = 15`.
  - *Résultat attendu :* Réception exacte de `#16..#20` sans perte ni doublon ; aucun dépôt local non explicitement soumis à une tâche hébergée n'est envoyé au cloud.

### 4.6 Critères d'acceptation
- [ ] Promotion et restauration en 1 clic vers des artefacts identifiés et vérifiés par digest sur Cloudflare R2/Pages.
- [ ] Aucun secret ni rôle de déploiement cloud accessible au code exécuté dans la tâche ECS Fargate.
- [ ] Disponibilité de l'architecture cloud compatible avec la cible SLA de **99,5 %** au lancement.

### 4.7 Definition of Done
- Service Cloud Axum, adaptateur ECS Fargate et pipeline de publication Cloudflare R2/Pages livrés et validés.

### 4.8 Risques et rollback
- **Risques :** Dépassement de coût cloud en cas d'oubli de terminaison d'une tâche Fargate.
- **Mitigation :** Timeout matériel strict (`stopTimeout` + watchdog de réconciliation) détruisant toute tâche Fargate dépassant le budget de durée de la `TaskSpec`.
