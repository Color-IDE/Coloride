**Domaine :** Extensibilité & Compatibilité Écosystème VS Code

**Priorité :** P1
**Complexité :** Élevée
**Estimation :** 5 jours (40 h)
**Dépendances :** [LOT-004](./LOT-004.md), [LOT-006](./LOT-006.md), [LOT-010](./LOT-010.md), [LOT-012](./LOT-012.md), [LOT-013](./LOT-013.md)

### 4.1 Objectif
Implémenter un **Émulateur / Adaptateur d'Extensions VS Code (`VS Code Extension Host Shim`)** capable de télécharger, installer et exécuter des extensions `.vsix` issues d'**OpenVSX** dans un processus Worker isolé par la Sandbox OS native ([LOT-012](./LOT-012.md)), en traduisant la surface API `vscode.*` (`commands`, `workspace`, `languages`, `window`, `env`) vers le **Host Rust (`ropey`)** et **CodeMirror 6**, sans jamais dégrader la réactivité de frappe (`p95 ≤ 16 ms`) ni contourner le `Policy Engine`.

### 4.2 Périmètre
- **IN :**
  - **Client & Installateur OpenVSX (`.vsix`) :** recherche, téléchargement, vérification d'intégrité (SHA-256/signature) et extraction de paquets `.vsix` depuis le registre **OpenVSX** ou un fichier local.
  - **Processus `VS Code Extension Host` isolé en Sandbox OS :** processus runtime JS/TS léger exécuté hors de la WebView principale et confiné par `crates/sandbox-runner` (accès disque restreint au worktree autorisé, réseau contrôlé par permissions déclarées, quotas CPU/RAM).
  - **Shim de l'API `vscode.*` (Surface principale compatible) :**
    - `vscode.commands` : `registerCommand`, `executeCommand` reliés à la palette de commandes Coloride.
    - `vscode.workspace` : `textDocuments`, `onDidOpenTextDocument`, `onDidChangeTextDocument`, `onDidSaveTextDocument`, `applyEdit` (`WorkspaceEdit`), `getConfiguration`, `fs` (filtré par le Host Rust et synchronisé avec `ropey` avec conversions UTF-16).
    - `vscode.languages` : `registerCompletionItemProvider`, `registerHoverProvider`, `registerCodeActionsProvider`, `registerDefinitionProvider`, `registerDocumentFormattingEditProvider`, `createDiagnosticCollection` projetés dans CodeMirror 6.
    - `vscode.window` : `activeTextEditor`, `visibleTextEditors`, `showInformationMessage` / `showWarningMessage` / `showErrorMessage`, `showQuickPick`, `showInputBox`, `createOutputChannel`, `createStatusBarItem`, `createTextEditorDecorationType` (traduit en `StateEffect` / `Decoration` CodeMirror 6).
  - **Gouvernance & Sécurité :** respect strict de *Workspace Trust* ([LOT-010](./LOT-010.md) : aucune extension à code actif ne s'exécute sur un dépôt non approuvé) et déclaration explicite des permissions par extension.
- **OUT :**
  - APIs internes non documentées de Monaco (`monaco.*` direct) ou APIs obsolètes propres au DOM interne d'Electron de VS Code.

### 4.3 Prérequis
- [LOT-004](./LOT-004.md) (CodeMirror 6 & IPC binaire), [LOT-006](./LOT-006.md) (chargeur déclaratif `.vsix` Niveau 1), [LOT-010](./LOT-010.md) (*Workspace Trust* & LSP), [LOT-012](./LOT-012.md) (Sandbox OS native), [LOT-013](./LOT-013.md) (`Policy Engine`).

### 4.4 Implémentation
1. **Protocole RPC binaire Host Rust ↔ Extension Host :** créer dans `crates/host-core` le superviseur `VsCodeExtensionHostSupervisor` communiquant par IPC local avec le processus `vscode-ext-host`. Les documents texte exposés dans `vscode.workspace.textDocuments` sont alimentés de manière asynchrone par les snapshots et deltas UTF-16 de `ropey` (sans jamais bloquer le thread d'édition de CodeMirror 6).
2. **Module virtuel `vscode` (Shim API) :** implémenter l'intercepteur `require('vscode')` / `import 'vscode'` fournissant les namespaces `commands`, `workspace`, `languages`, `window`, `Uri`, `Range`, `Position`, `Selection`, `TextEdit`, `WorkspaceEdit`, `Diagnostic`, `EventEmitter`, `Disposable`.
3. **Pont `WorkspaceEdit` & `DecorationType` → Host Rust / CodeMirror 6 :**
   - Lorsqu'une extension appelle `vscode.workspace.applyEdit(edit)`, l'opération est transmise au Host Rust comme une `EditorTransaction` d'origine `Extension(ext_id)` vérifiant la `base_revision`.
   - Lorsqu'une extension applique `editor.setDecorations(decorationType, ranges)`, le Host Rust projette les plages UTF-16 vers CodeMirror 6 sur une couche de décoration séparée n'écrasant jamais les 5 états de validation Coloride (`🟢/🟡/🔴/🟠/🔵`).
4. **Isolation & Quotas :** lancer le processus `vscode-ext-host` dans l'enveloppe `OsNativeSandbox` ([LOT-012](./LOT-012.md)) : blocage de `~/.ssh`, `~/.aws`, quota mémoire (ex. 512 Mo max) et watchdog de CPU (toute extension qui bloque la boucle d'événements est suspendue sans aucun impact sur l'UI ni sur CodeMirror 6).

### 4.5 Tests obligatoires
- **Test d'intégration E2E d'extensions `.vsix` réelles (Bloquant) :**
  - *Scénario :* Installer un paquet `.vsix` contenant un thème, des snippets, une commande `vscode.commands.registerCommand`, un `CompletionItemProvider` (`vscode.languages`), un `DiagnosticCollection` et un décorateur de lignes (`createTextEditorDecorationType`).
  - *Préconditions :* Workspace approuvé (*Workspace Trust* actif).
  - *Données d'entrée :* Activation sur `onLanguage:typescript` et ouverture d'un fichier `.ts`.
  - *Résultat attendu :* La commande apparaît dans la palette et s'exécute ; les complétions, diagnostics et décorations de l'extension s'affichent aux bons offsets UTF-16 dans CodeMirror 6 ; les `WorkspaceEdit` mettent à jour `ropey` proprement.
- **Test de non-dégradation de la latence de frappe (< 16 ms) sous extension lente (Bloquant) :**
  - *Scénario :* Charger une extension mal codée qui exécute une boucle synchrone bloquante de `5 000 ms` à chaque événement `onDidChangeTextDocument` pendant que l'utilisateur tape dans CodeMirror 6.
  - *Résultat attendu :* La latence de frappe dans CodeMirror 6 reste à **p95 ≤ 16 ms** ; l'Extension Host isolé est détecté comme gelé par le watchdog du Host Rust, l'extension fautive est suspendue et une notification informe l'utilisateur.
- **Test de sécurité d'une extension `.vsix` malveillante (Bloquant) :**
  - *Scénario :* Installer une extension tentant de lire `~/.ssh/id_rsa`, d'exécuter un script sur un dépôt non approuvé ou de modifier silencieusement un état `🟢 ✓ Validé` du Juge.
  - *Résultat attendu :* Accès à `~/.ssh` bloqué par la Sandbox OS ; activation refusée sur dépôt non approuvé ; impossibilité pour l'extension de falsifier un objet `Evidence` ou l'état `🟢` du Juge.

### 4.6 Critères d'acceptation
- [ ] Installation en 1 clic d'extensions `.vsix` depuis OpenVSX ou fichier local.
- [ ] Émulation fonctionnelle des namespaces `vscode.commands`, `vscode.workspace`, `vscode.languages` et `vscode.window` reliés à `ropey` et CodeMirror 6.
- [ ] `0` impact d'une extension lente ou plantée sur la latence de frappe de CodeMirror 6 (**p95 ≤ 16 ms** garanti).
- [ ] Confinement de l'Extension Host par la Sandbox OS native et respect strict de *Workspace Trust*.

### 4.7 Definition of Done
- Superviseur `VsCodeExtensionHostSupervisor`, shim API `vscode.*`, client OpenVSX et pont CodeMirror 6 livrés et validés par les tests d'intégration, de performance et de sécurité.

### 4.8 Risques et rollback
- **Risques :** Extensions utilisant des WebViews personnalisées complexes (`vscode.window.createWebviewPanel`).
- **Mitigation :** Isoler tout `WebviewPanel` d'extension dans une iframe sandboxée avec la même politique d'isolation stricte d'origine que le `Preview Service` ([LOT-016](./LOT-016.md)), sans aucun accès à `window.__TAURI__`.
