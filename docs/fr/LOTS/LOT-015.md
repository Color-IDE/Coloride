**Dépendances :** [LOT-004](./LOT-004.md), [LOT-010](./LOT-010.md), [LOT-013](./LOT-013.md), [LOT-014](./LOT-014.md)
**Parallélisable avec :** Aucun (assemblage central de la boucle de valeur du MVP)

### 4.1 Objectif
Réaliser la boucle complète du **Juge déterministe Coloride** : compilation des `ChangeSet` ancrés sur l'AST (`Tree-sitter`) ou blocs `SEARCH/REPLACE` vérifiés, exécution prioritaire des tests impactés (*Test Impact Analysis* en < 2 s) + `vtsls` + Biome dans la sandbox OS native, boucle d'auto-correction limitée à 2 essais, attribution déterministe des états `🟢/🟡/🔴/🟠/🔵` liés au hash de la révision, et revue interactive via `@codemirror/merge`.

### 4.2 Périmètre
- **IN :**
  - Compilateur `AstChangeSetCompiler` dans le Host Rust traduisant les opérations AST (`Tree-sitter`) ou blocs `SEARCH/REPLACE` ancrés sur les symboles en patch exact sur snapshots immuables.
  - Contrôle strict de la révision de base (`base_revision`) : si l'utilisateur a modifié le fichier pendant la tâche, réévaluation de l'ancrage AST si les symboles sont disjoints ou présentation explicite du conflit sans jamais écraser le travail humain ni appliquer sur de mauvais offsets.
  - Pipeline de vérification du Juge dans la sandbox OS ([LOT-012](./LOT-012.md)) sur le `git worktree` ([LOT-011](./LOT-011.md)) :
    1. Vérification syntaxique et formatage/lint **Biome** + typage **`vtsls`**.
    2. Exécution prioritaire des **tests impactés** (*Test Impact Analysis* de [LOT-007](./LOT-007.md)) pour fournir un premier verdict `🟢/🔴` en **< 2 secondes**, suivie de la suite pertinente.
    3. Construction de la preuve `Evidence` signée avec le `tested_snapshot_hash` et le `checkpoint_ref`.
  - Boucle d'auto-correction : en cas d'état `🔴 ✕ Échec`, renvoi automatique du diagnostic structuré à l'agent jusqu'à **2 cycles maximum** (arrêt immédiat si le même échec se répète).
  - Intégration de `@codemirror/merge` (diff unifié et côte-à-côte) dans l'inspecteur droit avec actions `[✓ Accepter]`, `[✕ Rejeter]`, `[Demander un ajustement]`.
  - Re-vérification incrémentale automatique en arrière-plan lorsqu'une plage `🟠 ⟳ Validation périmée` (modifiée localement par l'utilisateur après les tests) se stabilise.
- **OUT :**
  - Preuve runtime du navigateur `Preview Service` (intégrée dans [LOT-016](./LOT-016.md)).

### 4.3 Prérequis

### 4.4 Implémentation
1. Implémenter `AstChangeSetCompiler::compile(&Rope, &Tree, &ChangeSet) -> Result<CompiledPatch, ConflictReport>` : localise le symbole cible dans l'AST, vérifie l'empreinte du bloc source et calcule les offsets UTF-8/UTF-16 exacts ainsi que le `result_digest`.
2. Implémenter `JudgePipeline::evaluate_changeset` : crée le checkpoint Git invisible, applique le patch dans le worktree isolé, lance en parallèle dans la sandbox OS native `biome check`, `vtsls` check et les tests impactés (`vitest related <files>`).
3. Appliquer la table de vérité stricte des couleurs Coloride :
   - `🟢 ✓ Validé` : compilation OK + `vtsls`/Biome 0 erreur + 100 % des tests impactés réussis sur le snapshot exact.
   - `🟡 ! À examiner` : patch en attente d'arbitrage humain, décision d'architecture ou avertissement non bloquant.
   - `🔴 ✕ Échec` : erreur de compilation, de type `vtsls`, règle Biome bloquante ou test en échec (après épuisement des ≤ 2 retries auto).
   - `🟠 ⟳ Validation périmée` : plage précédemment `🟢` modifiée localement par l'utilisateur.
   - `🔵 • Source inchangée` : code d'origine non modifié par la tâche courante.
4. Intégrer `@codemirror/merge` dans `packages/editor-cm6` pour la revue interactive des zones `🟡` et la fusion atomique vers le buffer principal.

### 4.5 Tests obligatoires
- **Test E2E de la boucle du Juge avec auto-correction bornée (Bloquant) :**
  - *Scénario :* Un agent soumet un `ChangeSet` contenant une régression unitaire au 1er essai (`🔴`), reçoit l'`Evidence` d'échec, soumet un correctif au 2e essai qui passe `vtsls`, Biome et les tests impactés.
  - *Résultat attendu :* Premier verdict sur les tests impactés obtenu en **< 2 s** ; attribution finale de l'état `🟢 ✓ Validé` avec `Evidence.tested_snapshot_hash == snapshot.content_blake3_hash`.
- **Test de conflit lors d'une modification utilisateur concurrente (Bloquant — Scénarios bloquants Section 5) :**
  - *Scénario :* Une tâche est lancée sur la révision `R10` de `auth.ts` ; pendant que l'agent génère son patch, l'utilisateur modifie la même fonction (passant en `R12`). Le patch de l'agent arrive avec `base_revision = 10`.
  - *Résultat attendu :* Le Host Rust détecte la divergence `R10 != R12` sur le nœud AST, refuse toute application aveugle sur des offsets décalés, préserve à 100 % la révision `R12` de l'utilisateur et présente le conflit dans la vue `@codemirror/merge`.
- **Test du cycle `🟢 → 🟠 → 🟢/🔴` après édition locale (Bloquant — Scénario bloquant Section 5) :**
  - *Scénario :* Obtenir l'état `🟢 ✓ Validé` sur une fonction, modifier un caractère dans CodeMirror 6, puis observer la re-vérification en arrière-plan.
  - *Résultat attendu :* Passage instantané en `🟠 ⟳ Validation périmée` à la frappe, puis retour automatique en `🟢 ✓ Validé` (si le test passe toujours) ou `🔴 ✕ Échec` (si la modification casse le test) dès la fin de la re-vérification incrémentale.

### 4.6 Critères d'acceptation
- [ ] Premier retour `🟢/🔴` sur les tests impactés fourni en **< 2 secondes** sur le scénario de référence.
- [ ] Limite stricte de **2 essais automatiques** en cas de `🔴 ✕ Échec`.
- [ ] Aucune application de patch sur de mauvais offsets ni aucun écrasement de modification utilisateur.
- [ ] Revue interactive complète (Accepter / Rejeter / Ajuster) via `@codemirror/merge`.

### 4.7 Definition of Done
- Compilateur `ChangeSet` AST, pipeline du Juge, états Coloride et `@codemirror/merge` livrés et validés.
- Clôture du jalon `M1.3 - The Judge & OS Sandbox`.

### 4.8 Risques et rollback
- **Risques :** Re-vérification en arrière-plan trop fréquente pendant que l'utilisateur continue de taper dans une zone `🟠`.
- **Mitigation :** Déclencher la re-vérification sandbox des zones `🟠` uniquement après un *debounce* de stabilisation (ex. 1,5 s sans frappe ou lors de la sauvegarde explicite).
