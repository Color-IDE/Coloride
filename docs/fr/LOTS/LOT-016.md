# LOT-016 — `Preview Service` isolé (Browser Loop) & Capture d'`Evidence` runtime

**Domaine :** Core Editor Engine & Validation Frontend
**Module :** `crates/host-core` (`Preview Service`), `apps/web-ui`, `crates/judge-orchestrator`
**Jalon :** `M1.4 - MVP Launch Ready`
**Priorité :** P0
**Complexité :** Moyenne
**Estimation :** 3 jours (24 h)
**Dépendances :** [LOT-015](./LOT-015.md)
**Parallélisable avec :** Début de [LOT-017](./LOT-017.md)

---

### 4.1 Objectif
Intégrer le **`Preview Service (Browser Loop)`** sur une origine isolée sans aucun accès au pont IPC Tauri, capturant automatiquement les erreurs runtime (`console.error`, exceptions non gérées, échecs réseau) et l'arbre DOM/accessibilité afin d'alimenter les preuves `Evidence` du Juge avant d'accorder l'état `🟢 ✓ Validé`.

### 4.2 Périmètre
- **IN :**
  - Serveur d'aperçu local sur origine distincte (port local éphémère dédié ou schéma isolé sans injection de `window.__TAURI__`) et iframe sandboxée (`sandbox="allow-scripts allow-forms"` sans `allow-same-origin` vers l'origine de contrôle).
  - Sonde d'instrumentation légère injectée dans l'aperçu capturant `window.onerror`, `unhandledrejection`, `console.error`, les requêtes réseau en échec et un résumé de l'arbre DOM / accessibilité.
  - Intégration dans `Evidence` ([LOT-015](./LOT-015.md)) : un composant UI qui compile mais produit une erreur runtime ou un écran blanc (`ErrorBoundary`) au rendu est classé `🔴 ✕ Échec` et renvoyé à l'agent avec sa trace exacte.
- **OUT :**
  - Sélection visuelle d'éléments du catalogue No-Code ([LOT-021](./LOT-021.md)).

### 4.3 Prérequis
- [LOT-015](./LOT-015.md).

### 4.4 Implémentation
1. Créer `PreviewServer` dans `crates/host-core` servant le build/dev server du worktree sur une origine distincte avec en-têtes `Content-Security-Policy` et `Cross-Origin-Opener-Policy` stricts.
2. Vérifier par test d'assertion au chargement de l'aperçu que `typeof window.__TAURI__ === "undefined"` et `typeof window.__TAURI_INTERNALS__ === "undefined"`.
3. Collecter les télémétries runtime de l'aperçu (`PreviewRuntimeReport { uncaught_exceptions, console_errors, failed_requests, a11y_tree_summary }`) et les rattacher à l'`Evidence` du snapshot courant.

### 4.5 Tests obligatoires
- **Test de sécurité d'aperçu généré malveillant (Bloquant — Scénario bloquant Section 5) :**
  - *Scénario :* Charger dans le `Preview Service` un composant malveillant tentant d'invoquer `window.__TAURI__`, d'accéder à `window.top.document`, de lire les cookies/tokens de l'IDE et de contacter l'origine de contrôle.
  - *Résultat attendu :* Refus total par le navigateur/WebView ; `0` accès au pont Tauri, aux credentials ou à l'origine de contrôle.
- **Test de refus de l'état `🟢` sur crash runtime React (Bloquant) :**
  - *Scénario :* Un agent génère un composant `.tsx` sans aucune erreur TypeScript ni Biome, mais qui déclenche une exception `ReferenceError` ou un `console.error` au montage dans le `Preview Service`.
  - *Résultat attendu :* `Evidence.preview_report` contient l'erreur ; le Juge refuse `🟢 ✓ Validé`, attribue `🔴 ✕ Échec` et déclenche la boucle de correction avec la trace runtime.

### 4.6 Critères d'acceptation
- [ ] Isolation d'origine à 100 % entre le `Preview Service` et l'interface de contrôle Tauri.
- [ ] Aucun état `🟢 ✓ Validé` n'est accordé à une tâche frontend si le `Preview Service` détecte un crash ou un `console.error` non géré.

### 4.7 Definition of Done
- `Preview Service` isolé et intégration dans `Evidence` livrés et validés sur les 3 OS.

### 4.8 Risques et rollback
- **Risques :** Gel de l'aperçu en cas de boucle `while(true)` synchrone dans le code utilisateur.
- **Mitigation :** Timeout de rendu (3 s) avec bouton et mécanisme automatique de terminaison/rechargement du frame d'aperçu isolé.
