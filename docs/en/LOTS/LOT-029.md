# LOT-029 — VS Code Extension Emulator (`VS Code Extension Host Shim` & OpenVSX `.vsix`)

> 🇫🇷 [Version française](../fr/LOTS/LOT-029.md)

**Domain:** Extensibility & VS Code Ecosystem Compatibility
**Module:** `crates/host-core` (`ExtensionHostManager`), `packages/editor-cm6` (`vscode.languages` / `Decorations` adapters), `apps/web-ui` (OpenVSX Extensions Panel), `vscode-ext-host` Worker isolated by `crates/sandbox-runner`
**Milestone:** `M2.0 - Closed Beta` / `M3.0 - V1`
**Priority:** P1 | **Complexity:** High | **Estimate:** 5 days (40 h)
**Dependencies:** [LOT-004](./LOT-004.md), [LOT-006](./LOT-006.md), [LOT-010](./LOT-010.md), [LOT-012](./LOT-012.md), [LOT-013](./LOT-013.md)

### 4.1 Objective
Implement a **VS Code Extension Emulator / Adapter (`VS Code Extension Host Shim`)** capable of downloading, installing, and running `.vsix` extensions from **OpenVSX** inside a dedicated Worker process isolated by the native OS Sandbox ([LOT-012](./LOT-012.md)), translating the `vscode.*` API surface (`commands`, `workspace`, `languages`, `window`, `env`) to the **Native Rust Host (`ropey`)** and **CodeMirror 6**, without ever degrading keystroke latency (`p95 ≤ 16 ms`) or bypassing the `Policy Engine`.

### 4.2 Scope
- **IN:**
  - **OpenVSX (`.vsix`) Client & Installer:** search, download, SHA-256/signature verification, and extraction of `.vsix` packages from **OpenVSX** or local files.
  - **OS-Sandboxed `vscode-ext-host` Process:** lightweight JS/TS runtime process running outside the main WebView and confined by `crates/sandbox-runner` (filesystem access restricted to the authorized worktree, network governed by declared permissions, strict CPU/RAM quotas).
  - **`vscode.*` API Shim (Core Compatible Surface):**
    - `vscode.commands`: `registerCommand`, `executeCommand` wired to Coloride's Command Palette.
    - `vscode.workspace`: `textDocuments`, `onDidOpenTextDocument`, `onDidChangeTextDocument`, `onDidSaveTextDocument`, `applyEdit` (`WorkspaceEdit`), `getConfiguration`, `fs` (filtered by the Rust Host and synced asynchronously with `ropey` using UTF-16 offsets).
    - `vscode.languages`: `registerCompletionItemProvider`, `registerHoverProvider`, `registerCodeActionsProvider`, `registerDefinitionProvider`, `registerDocumentFormattingEditProvider`, `createDiagnosticCollection` projected into CodeMirror 6.
    - `vscode.window`: `activeTextEditor`, `visibleTextEditors`, `showInformationMessage` / `showWarningMessage` / `showErrorMessage`, `showQuickPick`, `showInputBox`, `createOutputChannel`, `createStatusBarItem`, `createTextEditorDecorationType` (translated into a dedicated CodeMirror 6 `StateEffect` / `Decoration` layer).
  - **Governance & Security:** strict enforcement of *Workspace Trust* ([LOT-010](./LOT-010.md): zero active code extensions run on untrusted repositories) and explicit permission prompts.
- **OUT:**
  - Undocumented internal Monaco APIs (`monaco.*` globals) or legacy Electron-specific DOM internals.

### 4.3 Prerequisites
- [LOT-004](./LOT-004.md), [LOT-006](./LOT-006.md), [LOT-010](./LOT-010.md), [LOT-012](./LOT-012.md), [LOT-013](./LOT-013.md).

### 4.4 Implementation
1. **Binary RPC Protocol (Rust Host ↔ Extension Host):** implement `VsCodeExtensionHostSupervisor` in `crates/host-core` streaming asynchronous UTF-16 document snapshots and deltas from `ropey` to `vscode.workspace.textDocuments` without blocking CodeMirror 6's editing thread.
2. **Virtual `vscode` Module Shim:** intercept `require('vscode')` / `import 'vscode'` to expose `commands`, `workspace`, `languages`, `window`, `Uri`, `Range`, `Position`, `Selection`, `TextEdit`, `WorkspaceEdit`, `Diagnostic`, `EventEmitter`, and `Disposable`.
3. **`WorkspaceEdit` & `DecorationType` Bridge → Rust Host / CodeMirror 6:**
   - Translate `vscode.workspace.applyEdit(edit)` into an `EditorTransaction` with origin `Extension(ext_id)` verified against `base_revision` in `host-core`.
   - Project `editor.setDecorations(decorationType, ranges)` into a separate CodeMirror 6 decoration facet that never overwrites the 5 Coloride validation states (`🟢/🟡/🔴/🟠/🔵`).
4. **OS Sandbox Confinement & Watchdog:** run `vscode-ext-host` inside `OsNativeSandbox` ([LOT-012](./LOT-012.md)) blocking `~/.ssh` and `~/.aws`, enforcing a memory cap, and running an event-loop watchdog that suspends any unresponsive extension without affecting the IDE.

### 4.5 Mandatory Tests
- **End-to-End Real `.vsix` Extension Integration Test (Blocking):** Install a `.vsix` extension providing a command, a `CompletionItemProvider`, a `DiagnosticCollection`, and line decorations (`createTextEditorDecorationType`); verify all features render at exact UTF-16 offsets in CodeMirror 6 and `WorkspaceEdit` updates `ropey`.
- **Zero Typing Latency Degradation (< 16 ms) Under Blocking Extension Test (Blocking):** Load an extension executing a synchronous `5,000 ms` `while` loop on every `onDidChangeTextDocument` while typing in CodeMirror 6; verify CodeMirror 6 typing stays at **p95 ≤ 16 ms** and the Rust watchdog suspends the frozen extension.
- **Malicious `.vsix` Extension Security Test (Blocking):** Install an extension attempting to read `~/.ssh/id_rsa`, run on an untrusted workspace, or spoof a `🟢 ✓ Validated` Judge badge; verify 100% OS Sandbox refusal, *Workspace Trust* blocking, and inability to forge Judge `Evidence`.

### 4.6 Acceptance Criteria
- [ ] 1-click installation of `.vsix` extensions from OpenVSX or local files.
- [ ] Functional emulation of `vscode.commands`, `vscode.workspace`, `vscode.languages`, and `vscode.window` bridged to `ropey` and CodeMirror 6.
- [ ] `0` impact from slow or crashed extensions on CodeMirror 6 typing latency (**p95 ≤ 16 ms** guaranteed).
- [ ] Full confinement of the Extension Host by the native OS Sandbox and *Workspace Trust*.

### 4.7 Definition of Done
`VsCodeExtensionHostSupervisor`, `vscode.*` API shim, OpenVSX client, and CodeMirror 6 bridge delivered and validated across integration, performance, and security test suites.

### 4.8 Risks & Rollback
- **Risk:** Extensions creating custom WebViews (`vscode.window.createWebviewPanel`).
- **Mitigation:** Isolate any extension `WebviewPanel` inside a sandboxed iframe enforcing the exact same origin isolation policy as `Preview Service` ([LOT-016](./LOT-016.md)), with zero access to `window.__TAURI__`.
