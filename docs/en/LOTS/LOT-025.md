# LOT-025 — DevOps Workspace: Terraform/Ansible/CI/K8s Connectors & Plan Executor

**Module:** `crates/judge-orchestrator`, `crates/sandbox-runner`, `apps/web-ui` (Infrastructure Workspace)
**Milestone:** `M3.0 - V1 Multi-Personas`
**Priority:** P1 | **Complexity:** High | **Estimate:** 4.5 days (36 h)
**Dependencies:** [LOT-013](./LOT-013.md), [LOT-018](./LOT-018.md)

---

### 4.1 Objective
Deliver the specialized **DevOps Engineer** workspace: generation and validation of **Terraform** plans, **Ansible** playbooks, and **GitHub Actions** workflows, read-only **Kubernetes** diagnostics, protection of Terraform plans as sensitive artifacts (secret redaction and encryption), and infrastructure mutation exclusively through a **separate deployment executor** using short-lived identities after human inspection and approval of the exact plan.

### 4.2 Scope
- **IN:** Specialized HCL (Terraform) and YAML (Ansible, GitHub Actions, K8s) editors in CodeMirror 6 and Infrastructure Workspace; **read-only Kubernetes diagnostics** (pods, events, deployment status, correlated logs, zero access to K8s `Secret` objects); sandboxed `terraform plan` generation treated as a **sensitive encrypted/redacted artifact**; and **separate `IsolatedDeploymentExecutor`** using temporary OIDC/STS cloud credentials and verifying `Approval::is_valid_for(target_env, tfplan_sha256_digest, now)` before applying.
- **OUT:** Direct `terraform apply` or `kubectl apply/delete` privileges for the AI agent.

### 4.3 Prerequisites
- [LOT-013](./LOT-013.md) and [LOT-018](./LOT-018.md).

### 4.4 Implementation
1. Implement `TerraformPlanSanitizer`: run `terraform plan -out=tfplan.bin` and `terraform show -json tfplan.bin` inside the sandbox, encrypt `tfplan.bin` at rest, and redact all `sensitive_values` and `AclAndSecretScanner` matches before displaying in the UI or sending to any LLM.
2. Implement `K8sReadOnlyDiagnostics` restricting allowed verbs to `get`, `list`, `watch` on non-secret resources.
3. Implement `IsolatedDeploymentExecutor` verifying the approved plan digest and target environment before acquiring short-lived credentials, transitioning to `NeedsReconciliation` without blind retry if interrupted.

### 4.5 Mandatory Tests
- **Terraform Plan Secret Protection Test (Blocking):** Generate a `terraform plan` containing a database password in state; verify `tfplan.bin` is encrypted at rest and the password is 100% redacted (`(sensitive value redacted)`) in both the UI and LLM context.
- **DevOps Agent vs Deployment Executor Separation Test (Blocking):** Verify the DevOps agent is blocked from running `terraform apply` or `kubectl delete`, and verify `IsolatedDeploymentExecutor` rejects applying a `staging`-approved plan to `production` or applying a 1-byte modified `tfplan.bin`.

### 4.6 Acceptance Criteria
- [ ] Terraform plans treated end-to-end as encrypted and redacted sensitive artifacts.
- [ ] Kubernetes diagnostics strictly read-only (excluding K8s `Secret` objects).
- [ ] Every infrastructure mutation requires human inspection of the target and exact plan, executed by the separate executor with temporary identities.

### 4.7 Definition of Done
Terraform, Ansible, GitHub Actions, read-only Kubernetes connectors, and `IsolatedDeploymentExecutor` delivered and validated.

### 4.8 Risks & Rollback
- **Risk:** Network interruption mid-`terraform apply`.
- **Mitigation:** Transition immediately to `NeedsReconciliation`, block automatic retries, and run a read-only `terraform plan -refresh-only` to present actual state drift to the DevOps engineer.
