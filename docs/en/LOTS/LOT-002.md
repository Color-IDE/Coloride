### 4.1 Objective
Define in Rust and automatically project to TypeScript the 9 canonical technical contracts of Coloride, the 11-state task lifecycle, and the 5 Coloride validation states, with schema versioning and cryptographic digest invalidation for approvals.

### 4.2 Scope
- **IN:** Rust definitions (`serde` + `ts-rs`/`specta` + binary serialization) for `EditorTransaction`, `EditorSnapshot`, `TaskSpec`, `ContextBundle`, `ModelProvider`, `ToolCall`, `ChangeSet`, `Evidence`, `Approval`, `ColorideValidationState`, and `TaskState`; automated TypeScript generation into `packages/protocol-types`.
- **OUT:** Execution engines consuming these contracts.

### 4.3 Prerequisites
- [LOT-001](./LOT-001.md) validated.

### 4.4 Implementation
1. Define explicit offset newtypes (`Utf8ByteOffset(u32)`, `Utf16CodeUnitOffset(u32)`, `LineCol`) to prevent unit confusion between Rust/Tree-sitter (UTF-8) and CodeMirror/LSP/VS Code (UTF-16).
2. Implement `EditorTransaction` and `EditorSnapshot` (separating `interactive_revision`, `journaled_revision`, and `disk_saved_revision`).
3. Implement `Evidence` and `Approval::is_valid_for(&self, target_env, action_digest, now) -> bool` invalidating any approval if the patch, target, or plan digest changes by a single bit.
4. Generate `packages/protocol-types` bindings and enforce zero drift in CI.

### 4.5 Mandatory Tests
- **Contract Serialization & Round-Trip Tests (Blocking):** JSON and binary round-trips for all 9 contracts and 11 task states.
- **Approval Invalidation Security Test (Blocking):** Mutating 1 bit of `changeset_digest` or changing `target_env` causes `Approval::is_valid_for` to return `false`.

### 4.6 Acceptance Criteria
- [x] All 9 contracts are exported in `@coloride/protocol-types` with `0` usage of `any`.
- [x] CI fails automatically if a Rust contract changes without regenerating `packages/protocol-types`.
- [x] Any mutation of patch, target, or plan invalidates the corresponding `Approval`.

### 4.7 Definition of Done
Rust and TypeScript contracts generated, round-trip and digest invalidation tests passing, anti-drift check active in CI.

### 4.8 Risks & Rollback
- **Risk:** 64-bit integer precision loss in JavaScript (`Number.MAX_SAFE_INTEGER`).
- **Mitigation:** Use `u32` for offsets/revisions or typed strings/`BigInt` for 64-bit IDs.
