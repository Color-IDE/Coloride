### 4.1 Objective
Build the deterministic governance core in `crates/judge-orchestrator`: the persistent 11-state task machine, the `Policy Engine` evaluating permissions/targets/preconditions, the `BudgetLedger` (upfront reservation and circuit breakers), and the idempotent `Tool Broker` immune to prompt injection.

### 4.2 Scope
- **IN:** Persistent state machine (`Created → ContextReady → Planned → Running → Verifying → AwaitingReview → Applied` + `Paused`, `Failed`, `Cancelled`, `NeedsReconciliation`) with durable pre/post-action journaling; `lease` and `generation_token` preventing expired workers from publishing; deterministic `Policy Engine`; `BudgetLedger` reserving maximum estimated cost prior to calls and capping auto-retries at **2 cycles**; and idempotent `Tool Broker` transitioning to `NeedsReconciliation` if interrupted during an external action (zero blind retries).
- **OUT:** Model adapters and ACP bridge ([LOT-014](./LOT-014.md)), AST patch compilation ([LOT-015](./LOT-015.md)).

### 4.3 Prerequisites
- [LOT-002](./LOT-002.md) and [LOT-012](./LOT-012.md).

### 4.4 Implementation
1. Implement `TaskStateRepository` with outbox journaling and atomic `generation_token` verification.
2. Record `ActionIntent(idempotency_key)` before any external side-effect action; if an unacknowledged intent is found on recovery, transition to `NeedsReconciliation`.
3. Implement `BudgetLedger::reserve_before_call` and the loop detector stopping after 2 automatic retries or repeated identical failure signatures.
4. Ensure `PolicyEngine` evaluates only signed `TaskSpec` and `Approval` structs—never untrusted repository files, comments, or MCP responses.

### 4.5 Mandatory Tests
- **Crash After External Action & Expired Worker Rejection (Blocking — Section 5 Blocking Scenario):** Crash worker `W1` (`generation_token = 1`) mid-action, recover on `generation_token = 2`, and reject late writes from `W1`; verify transition to `NeedsReconciliation` with `0` blind retries.
- **Prompt Injection via File or MCP Security Test (Blocking — Section 5 Blocking Scenario):** Inject privilege-escalation instructions in source comments and MCP tool output; verify 100% rejection by `PolicyEngine`.
- **Budget & Loop Circuit Breaker Test (Blocking):** Exceeding reserved tokens or repeating the same failure twice halts execution immediately (`Paused` or `Failed`).

### 4.6 Acceptance Criteria
- [ ] Transactional persistence of all 11 states protected by `generation_token` and `idempotency_key`.
- [ ] Zero blind retries of external actions after an interruption.
- [ ] Maximum 2 automatic correction cycles by default; immediate stop on repeated error.
- [ ] Complete immunity of `PolicyEngine` permissions against prompt injection.

### 4.7 Definition of Done
State machine, `Policy Engine`, `BudgetLedger`, and `Tool Broker` delivered and tested in `crates/judge-orchestrator`.

### 4.8 Risks & Rollback
- **Risk:** Leaked budget reservations on cancelled model streams.
- **Mitigation:** RAII `BudgetReservationGuard` automatically releasing unused budget on `Drop` or cancellation.
