# LOT-010 — Fast Quality Integration (`vtsls` LSP, Biome) & Terminal/DAP

> 🇫🇷 [Version française](../fr/LOTS/LOT-010.md)

**Domain:** Core Editor Engine
**Module:** `crates/host-core`, `packages/editor-cm6`, `apps/web-ui`
**Milestone:** `M1.2 - Context & Fast Quality`
**Priority:** P0 | **Complexity:** Medium | **Estimate:** 4 days (32 h)
**Dependencies:** [LOT-004](./LOT-004.md), [LOT-005](./LOT-005.md)

---

### 4.1 Objective
Connect in `crates/host-core` the TypeScript language server (`vtsls`, with an adapter ready for `tsgo`), the Rust linter/formatter **Biome**, the `xterm.js` terminal over binary Tauri `Channel`, and the JavaScript Debug Adapter (DAP), guarded by **Workspace Trust** (blocking automatic execution on untrusted repositories).

### 4.2 Scope
- **IN:** Background supervision (post-*Lazy Boot*) of `vtsls` and `Biome` fed directly from `ropey` buffers; projection of diagnostics, definitions, references, rename, formatting, and completions into CodeMirror 6 with strict revision checking; semantic graph enrichment (`ConfidenceLevel::ExactSemantic`); binary `xterm.js` + `portable-pty` terminal service; JS/TS DAP client; and *Workspace Trust* gate.
- **OUT:** Isolated execution of agent commands inside the OS sandbox ([LOT-012](./LOT-012.md)).

### 4.3 Prerequisites
- [LOT-004](./LOT-004.md) and [LOT-005](./LOT-005.md).

### 4.4 Implementation
1. Implement `WorkspaceTrustGate` blocking repository-local binaries, hooks, startup scripts, and DAP until explicit user trust approval.
2. Feed `vtsls` and `Biome` directly from `host-core` `ropey` deltas with UTF-16 offsets and tag every returned diagnostic with its `base_revision`.
3. Discard stale diagnostics in `packages/editor-cm6` if the target range was modified after `base_revision`.
4. Connect `xterm.js` and DAP via binary Tauri `Channel` streams batched at `16 ms`.

### 4.5 Mandatory Tests
- **Untrusted Workspace Security Test (Blocking):** Opening an untrusted repository containing a trojan `node_modules/.bin/biome` or `.git/hooks` launches `0` external processes while Lezer highlighting and CodeMirror 6 editing work normally.
- **Stale Diagnostic Rejection Test (Blocking — Section 5 Blocking Scenario):** A delayed diagnostic for revision `R4` arriving after the user edited the line in `R5` is discarded and never applied to shifted offsets.

### 4.6 Acceptance Criteria
- [ ] Two-speed highlighting active: local Lezer in **< 2 ms**, followed by asynchronous Tree-sitter/`vtsls`/Biome enrichment without UI freezes.
- [ ] Zero stale LSP/Biome diagnostics applied to outdated offsets.
- [ ] Zero hooks, scripts, or workspace-local language servers executed on untrusted repositories.

### 4.7 Definition of Done
`vtsls`, Biome, `xterm.js`, JS DAP, and *Workspace Trust* delivered and tested. Closes milestone `M1.2`.

### 4.8 Risks & Rollback
- **Risk:** Orphaned `vtsls` processes on abrupt Host exit.
- **Mitigation:** Bind all child processes to a process group / Job Object terminated on Host shutdown.
