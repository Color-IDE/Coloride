# LOT-008 — SQLite (`WAL`/`mmap`) Context Engine Storage, Secret Filtering & FTS5

---

### 4.1 Objective
Implement the warm local storage and instant lexical/structural search engine (**0 MB model download required on first launch**) built on SQLite in `WAL` + `mmap` mode, debounced `FTS5 (BM25)` indexing, strict priority for unsaved in-memory buffers, and mandatory ACL and secret filtering before indexing and before export.

### 4.2 Scope
- **IN:** Local SQLite database (`journal_mode = WAL`, `synchronous = NORMAL`, active `mmap_size`), `FTS5` (BM25) virtual tables coupled to `Tree-sitter` symbol tables, `AclAndSecretScanner` enforced both before indexing and before export (`.gitignore`, `.colorideignore`, API keys, tokens, PEM private keys, high-entropy secrets), debounced incremental indexer (`300 ms` candidate threshold), branch-switch invalidation, and *Unsaved Buffer Overlay* prioritizing in-memory `ropey` snapshots over stale disk files.
- **OUT:** Local MCP server and optional `sqlite-vec` embeddings ([LOT-009](./LOT-009.md)).

### 4.3 Prerequisites
- [LOT-007](./LOT-007.md).

### 4.4 Implementation
1. Create the SQLite schema (`files`, `ast_chunks`, `symbol_edges`, `fts_chunks`) with deterministic full rebuild from source files if missing or invalidated.
2. Run `AclAndSecretScanner` prior to any SQLite insert and prior to any `ContextBundle` export.
3. Implement `UnsavedBufferOverlay` so any document with `interactive_revision > disk_saved_revision` in `host-core` serves its live in-memory `ropey` snapshot.
4. Run debounced indexing on a low-priority Tokio thread pool.

### 4.5 Mandatory Tests
- **Unsaved Buffer Priority Test (Blocking):** Modify a constant in memory without saving to disk and query the Context Engine; verify the returned excerpt reflects the in-memory value and its `snapshot_hash`.
- **ACL & Secret Filtering Security Test (Blocking):** Place `.env`, AWS `AKIA...` keys, and GitHub `ghp_...` tokens in the workspace; verify `0` occurrences in the `.sqlite` database file or exported bundles.
- **Context Retrieval Performance Test (Blocking):** 100 hybrid queries (FTS5 BM25 + graph neighborhood) complete in **p95 ≤ 300 ms**.

### 4.6 Acceptance Criteria
- [ ] Instant search operational on first launch with **0 MB** of model downloads.
- [ ] Context retrieval latency measured at **p95 ≤ 300 ms**.
- [ ] 100% priority of unsaved in-memory buffers over disk files.
- [ ] `0` plaintext secrets stored in SQLite or exported.

### 4.7 Definition of Done
SQLite `WAL`/`mmap` + FTS5 + secret filter + buffer overlay delivered and tested in `crates/context-engine`.

### 4.8 Risks & Rollback
- **Risk:** Entropy false positives on lockfile integrity hashes.
- **Mitigation:** Exclude standard lockfiles from raw entropy heuristics while keeping exact credential pattern matching active everywhere.
