# LOT-021 — *Create* Mode (Visual AST Catalog) & *Learn* Mode (Pedagogical Micro-Agent)

> 🇫🇷 [Version française](../fr/LOTS/LOT-021.md)

**Domain:** Personas & UX/UI Adaptation (Phase 2 — Closed Beta)
**Module:** `apps/web-ui`, `crates/host-core`, `crates/judge-orchestrator`
**Milestone:** `M2.0 - Closed Beta (8-Chat Grid)`
**Priority:** P1 | **Complexity:** Medium | **Estimate:** 4 days (32 h)
**Dependencies:** [LOT-015](./LOT-015.md), [LOT-016](./LOT-016.md), [LOT-018](./LOT-018.md)

---

### 4.1 Objective
Deliver the UX and architectural adaptations for the **General Public / No-Code** persona (**Create** mode: React templates, component catalog with stable IDs, and visual property edits compiled into AST code changes) and the **Junior Developer** persona (**Learn** mode: pedagogical micro-agent explaining diagnostics, diffs, and costs prior to application).

### 4.2 Scope
- **IN:** *Create* mode: React templates, certified component catalog, visual element selection in `Preview Service` via stable `data-coloride-id` AST attributes, visual property inspector compiled by `AstChangeSetCompiler` into clean TypeScript/React code (arbitrary unrecognized components remain editable in code and visible in preview); *Learn* mode: pedagogical micro-agent explaining `vtsls`/Biome diagnostics, diffs, and test results before applying fixes; progressive UI disclosure preserving all security permissions across personas.
- **OUT:** Universal visual conversion of arbitrary imperative code outside the catalog.

### 4.3 Prerequisites
- [LOT-015](./LOT-015.md), [LOT-016](./LOT-016.md), [LOT-018](./LOT-018.md).

### 4.4 Implementation
1. Instrument the dev `Preview Service` to tag JSX elements with stable AST node identifiers.
2. Implement `VisualAstMutator` in `crates/host-core` translating visual inspector edits into Biome-formatted AST `ChangeSet` operations verified by the Judge.
3. Implement `PedagogicalAgentService` in `crates/judge-orchestrator` generating clear step-by-step explanations attached to `🟡`/`🔴` ranges.

### 4.5 Mandatory Tests
- **Bidirectional *Create* ↔ *Develop* Mode Fidelity Test (Blocking):** Edit 3 catalog components visually in *Create* mode, switch to *Develop* mode to add a custom hook-based component in CodeMirror 6, and switch back to *Create* mode; verify `.tsx` code remains valid (`🟢`) and serves as the single source of truth.
- **Persona Security Permission Invariance Test (Blocking):** Submitting an unauthorized `ToolCall` in *Create*, *Learn*, and *Develop* modes yields the exact same `Policy Engine` rejection.

### 4.6 Acceptance Criteria
- [ ] Every visual edit in *Create* mode produces a clean, Judge-verified AST diff on React source code.
- [ ] In *Learn* mode, every diagnostic or `🟡`/`🔴` patch includes a contextual explanation before application.
- [ ] No panel disappears automatically mid-task and the file tree remains accessible at all times.

### 4.7 Definition of Done
*Create* and *Learn* modes, visual AST catalog, and pedagogical micro-agent delivered and validated.

### 4.8 Risks & Rollback
- **Risk:** Overwriting a dynamic JSX expression (`prop={compute()}`) with a static literal from the visual inspector.
- **Mitigation:** Lock non-literal AST expressions in the visual inspector with a "Dynamic expression — click to edit in code" badge.
