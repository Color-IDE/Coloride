# LOT-003 — `ropey` Buffer Engine, WAL Journal & Crash Recovery (`host-core`)

**Domain:** Core Editor Engine (Rust Host)
**Module:** `crates/host-core` (`Workspace & Document Service`)
**Milestone:** `M1.1 - Core & Cockpit Shell`
**Priority:** P0 | **Complexity:** High | **Estimate:** 4 days (32 h)
**Dependencies:** [LOT-002](./LOT-002.md)

---

### 4.1 Objective
Implement in `crates/host-core` the single persistence authority for documents around `ropey::Rope`, featuring exact UTF-8 ↔ UTF-16 offset conversion, durable Write-Ahead Logging (WAL) prior to acknowledgment, atomic disk saves, external disk conflict detection, and automatic crash recovery.

### 4.2 Scope
- **IN:** In-memory `ropey::Rope` buffer manager indexed by `(document_id, session_generation)`, bidirectional `utf16_to_utf8` / `utf8_to_utf16` converter, append-only disk WAL journal (`WriteAheadJournal`), atomic disk save distinguishing `interactive_revision`, `journaled_revision`, and `disk_saved_revision`, external disk conflict detector, and crash recovery replay.
- **OUT:** CodeMirror 6 view ([LOT-004](./LOT-004.md)), Tree-sitter parsing ([LOT-007](./LOT-007.md)), Git checkpoints ([LOT-011](./LOT-011.md)).

### 4.3 Prerequisites
- [LOT-002](./LOT-002.md).

### 4.4 Implementation
1. Create `DocumentSession` holding `ropey::Rope`, revision counters, and `blake3` content hash.
2. Apply `EditorTransaction` atomically: verify `session_generation` and `base_revision`, convert UTF-16 ranges to UTF-8 byte offsets via `ropey`, mutate the `Rope`, append to the WAL journal, and emit `EditorSnapshot`.
3. Enforce the save invariant: `disk_saved_revision` updates only to the exact revision written to disk. If transaction `T+1` arrives while revision `T` is being flushed to disk, `has_unsaved_changes` remains `true` (never reporting a false "saved" state).
4. Implement `recover_workspace_from_journal()` to restore unsaved journaled revisions after a WebView or Host crash.

### 4.5 Mandatory Tests
- **Property-Based Tests (`proptest`, Blocking):** 1,000 random edit sequences mixing ASCII, CJK, multi-codepoint ZWJ emojis (`👩‍💻`), and `\n`/`\r\n` verifying 100% equivalence between `ropey` and a UTF-16 reference model.
- **Concurrent Save & Crash Recovery Test (Blocking — Section 5 Blocking Scenario):** Edit during an active disk save and simulate a process crash; verify no false "saved" state and 100% recovery of the latest journaled revision.
- **File Open Performance Test (Blocking):** Load a 1 MB local file into `Rope` in **p95 ≤ 50 ms** on the Rust side.

### 4.6 Acceptance Criteria
- [ ] 100% of `proptest` suites on revisions and UTF-8/UTF-16 conversions pass.
- [ ] Zero false "saved" status when an edit occurs during an ongoing disk write.
- [ ] Full restoration of the latest journaled revision after a simulated crash.

### 4.7 Definition of Done
`DocumentService` and WAL journal implemented in `crates/host-core` with `proptest` and crash recovery tests green across all 3 OSes.

### 4.8 Risks & Rollback
- **Risk:** `fsync` latency on Windows drives during rapid typing.
- **Mitigation:** Group-commit journal flushes over a few milliseconds while explicitly tracking `interactive_revision` vs `journaled_revision`.
