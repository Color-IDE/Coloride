### 4.1 Objective
Complete the V1/Enterprise isolation architecture with the **Firecracker** microVM backend on hardened Linux/KVM workers (fast microVM snapshot restore for workloads requiring dedicated kernel isolation) and the **Wasmtime/WASI** capability-based native plugin engine.

### 4.2 Scope
- **IN:** `FirecrackerRunner` orchestrating microVMs via `jailer` on compatible Linux/KVM hosts, restoring pre-warmed memory/disk snapshots in `< 50 ms`, isolating network via tap/namespace, and destroying the microVM upon task completion (never marketed as a native macOS/Windows runtime); and `WasiPluginHost` running WebAssembly WASI plugins with explicit manifest capabilities, pre-opened directories only, zero default network access, linear memory caps, and deterministic CPU *fuel* quotas.
- **OUT:** JS/TS `vscode.*` API surface emulation for `.vsix` extensions (handled in [LOT-029](./LOT-029.md) via the OS-sandboxed `VS Code Extension Host Shim`).

### 4.3 Prerequisites
- [LOT-012](./LOT-012.md) and [LOT-017](./LOT-017.md).

### 4.4 Implementation
1. Implement `FirecrackerRunner` implementing `SandboxRunner` ([LOT-012](./LOT-012.md)) over `jailer` + `firecracker` with CoW block overlays and `vsock` command execution.
2. Implement `WasiPluginHost` in `crates/host-core` using `wasmtime` with `WasiCtxBuilder` (no host env or network inheritance), `StoreLimits`, and `store.set_fuel(...)`.

### 4.5 Mandatory Tests
- **WASI Plugin Memory, CPU (*Fuel*) & Filesystem Confinement Test (Blocking):** Run a malicious WASI module attempting to open `/etc/passwd`, allocate 1 GB of RAM beyond its 64 MB limit, and spin in an infinite `loop {}`; verify `ENOTCAPABLE` on `/etc/passwd`, bounded allocation failure, and clean fuel-exhaustion termination in `< 100 ms` with zero impact on `host-core`.
- **Firecracker MicroVM Lifecycle & Isolation Test on Linux/KVM (Blocking):** Restore a Firecracker microVM from snapshot in `< 50 ms`, run a test suite, and verify complete destruction of the microVM and temporary network interfaces on task exit.

### 4.6 Acceptance Criteria
- [ ] WASI plugins confined by explicit capabilities, pre-opened files, and strict memory/CPU *fuel* quotas.
- [ ] Firecracker backend operational on hardened Linux/KVM workers with fast snapshot restore and guaranteed destruction.

### 4.7 Definition of Done
`FirecrackerRunner` and `WasiPluginHost` delivered, tested, and documented. **Milestone `M3.0 - V1 Multi-Personas` complete.**

### 4.8 Risks & Rollback
- **Risk:** Snapshot pool exhaustion under burst load.
- **Mitigation:** Admission queue with dynamic pre-warming and Linux/KVM worker autoscaling.
