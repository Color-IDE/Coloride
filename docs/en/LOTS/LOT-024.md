### 4.1 Objective
Deliver the specialized **DBA** workspace centered on **PostgreSQL**: read-only connection by default, schema and statistics introspection, read-only `EXPLAIN (FORMAT JSON)`, mandatory routing of `EXPLAIN ANALYZE` to a **sanitized clone** (because PostgreSQL actually executes the query during `EXPLAIN ANALYZE`), and an *expand/contract* migration executor with lock timeouts and controlled recovery after interruption.

### 4.2 Scope
- **IN:** Specialized SQL editor in CodeMirror 6 + PostgreSQL schema/index/statistics explorer; **read-only default PostgreSQL connector** (`default_transaction_read_only = on`, zero implicit admin privileges); execution plan comparator (`EXPLAIN (FORMAT JSON)` in read mode, `EXPLAIN ANALYZE` strictly restricted to an isolated **sanitized clone**); and *expand/contract* migration executor enforcing `lock_timeout` and `statement_timeout`, flagging destructive operations (`DROP`, `TRUNCATE`, table-rewriting locks), and transitioning to `NeedsReconciliation` on interruption (inspecting actual database state before any controlled resumption or backup restore).
- **OUT:** Non-PostgreSQL proprietary database engines in V1.

### 4.3 Prerequisites
- [LOT-013](./LOT-013.md) and [LOT-018](./LOT-018.md).

### 4.4 Implementation
1. Implement `PostgresSafeGuard` parsing SQL ASTs and blocking any DML/DDL mutation or `EXPLAIN ANALYZE` on connections not tagged `IsSanitizedClone`.
2. Implement `SanitizedDbCloneService` provisioning an isolated PostgreSQL clone with anonymized/sanitized data to run `EXPLAIN ANALYZE` and dry-run migration + rollback scripts prior to requesting `Approval`.
3. Implement `MigrationRunner` journaling every DDL step and inspecting `pg_catalog` / `pg_stat_activity` in `NeedsReconciliation` if interrupted.

### 4.5 Mandatory Tests
- **`EXPLAIN ANALYZE` & Read-Only Default Security Test (Blocking):** An SQL agent submits `EXPLAIN ANALYZE DELETE FROM users;` against a primary connection; verify immediate rejection and mandatory routing to the sanitized clone.
- **Interrupted SQL Migration Controlled Recovery Test (Blocking — Section 5 Blocking Scenario):** Interrupt a multi-step migration after step 1 of 3; verify transition to `NeedsReconciliation`, inspection of actual schema state, zero blind re-execution of step 1, and controlled resumption or backup restoration.

### 4.6 Acceptance Criteria
- [ ] Read-only PostgreSQL access by default; `0` `EXPLAIN ANALYZE` queries executed on production databases.
- [ ] Mandatory lock timeout (`lock_timeout`), backup check, and destructive change guard before any migration.
- [ ] 100% validation of the "Interrupted SQL Migration" blocking scenario.

### 4.7 Definition of Done
PostgreSQL connector, sanitized clone manager, *expand/contract* migration executor, and DBA UI delivered and qualified.

### 4.8 Risks & Rollback
- **Risk:** Irreversible DDL operation.
- **Mitigation:** Enforce *expand/contract* migration rules and verify a tested restore point prior to authorizing destructive DDL.
