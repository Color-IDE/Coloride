**Priority:** P2 | **Complexity:** Medium | **Estimate:** 4 days (32 h)

---

### 4.1 Objective
Qualify private deployments (**Customer VPC / On-Premise**), certify **GDPR / CNIL** obligations (processing register, verifiable deletion propagated across relational databases, FTS5 lexical indices, vector embeddings, and prompt caches, plus documented backup purge cycles), and demonstrate high availability (**99.9% SLA**) and disaster recovery targets (**RPO ≤ 15 min** and **RTO ≤ 4 h**) through live drills.

### 4.2 Scope
- **IN:** Isolated VPC / On-Premise deployment manifests (Helm/Terraform, private container registry, private desktop update server supporting air-gapped networks); **`GdprErasureOrchestrator`** propagating account, task, or workspace deletion across PostgreSQL/SQLite, FTS5 indices, `sqlite-vec` vector tables, prompt caches, and R2/S3 artifact buckets with post-erasure zero-residue verification; and multi-AZ continuous PostgreSQL WAL archiving (PITR) validated by a live Disaster Recovery drill demonstrating **RPO ≤ 15 min** and **RTO ≤ 4 h**.
- **OUT:** Features outside the 4-phase roadmap.

### 4.3 Prerequisites
- [LOT-027](./LOT-027.md).

### 4.4 Implementation
1. Implement `GdprErasureOrchestrator` executing multi-store cascading deletion followed by `verify_zero_residue` and issuing a timestamped erasure certificate, plus a *Deletion Tombstones Log* replayed automatically after any backup restore.
2. Package air-gapped VPC/On-Premise deployment charts and private desktop updater endpoints.
3. Execute and document the live multi-AZ failover and PITR recovery drill.

### 4.5 Mandatory Tests
- **Cascading GDPR Erasure Across Indices & Embeddings Test (Blocking — Section 5 Requirement):** Index a workspace containing `GDPR_CANARY_TOKEN_9942`, generate vector embeddings, prompt caches, checkpoints, and artifacts, trigger erasure, and scan all SQLite, PostgreSQL, FTS5, `sqlite-vec`, and object storage stores; verify `0` residual occurrences or orphaned vectors.
- **Live RPO ≤ 15 min / RTO ≤ 4 h Disaster Recovery Drill (Blocking — Section 5 Requirement):** Simulate complete loss of the primary PostgreSQL cluster and API nodes under continuous transaction load and execute the recovery runbook on the secondary site; verify **RPO ≤ 15 minutes** and **RTO ≤ 4 hours**.

### 4.6 Acceptance Criteria
- [ ] VPC / On-Premise deployment and private updates validated without public Internet dependency.
- [ ] Data deletion tested and propagated 100% across lexical indices and vector embeddings.
- [ ] **RPO ≤ 15 min** and **RTO ≤ 4 h** demonstrated via documented live exercise.

### 4.7 Definition of Done
VPC/On-Premise package, GDPR erasure orchestrator, and signed RPO/RTO drill report delivered. **Milestone `M4.0 - Scale & Enterprise` validated.**

### 4.8 Risks & Rollback
- **Risk:** Resurrection of deleted data when restoring an older database backup (*Tombstone Resurrection*).
- **Mitigation:** Replay the cryptographic *Deletion Tombstones Log* automatically before reopening traffic after any PITR restore.
