# LOT-011 — Invisible Git Time-Travel Checkpoints & *Copy-on-Write* Worktrees

> 🇫🇷 [Version française](../fr/LOTS/LOT-011.md)

**Domain:** Core Editor Engine & Git Isolation
**Module:** `crates/host-core` (`Git & Checkpoint Service`)
**Milestone:** `M1.3 - The Judge & OS Sandbox`
**Priority:** P0 | **Complexity:** Medium | **Estimate:** 3 days (24 h)
**Dependencies:** [LOT-003](./LOT-003.md)

---

### 4.1 Objective
Implement invisible Git **Time-Travel Checkpoints** (`refs/coloride/checkpoints/<task_id>`) capturing the exact workspace state prior to every agent action and enabling 1-click multi-file rollback without polluting `git log`, alongside `< 5 ms` *Copy-on-Write* `git worktree` provisioning.

### 4.2 Scope
- **IN:** Atomic Git tree/commit creation under `refs/coloride/checkpoints/<task_id>/<seq>` using a dedicated temporary index (without touching `HEAD`, `.git/index`, or `git log`), 1-click rollback with human-edit conflict protection, and *Copy-on-Write* `git worktree` provisioner (`cp -c` on macOS APFS, `cp --reflink=auto` on Linux, read-only package store junctions/hardlinks on Windows).
- **OUT:** OS sandbox execution inside the worktree ([LOT-012](./LOT-012.md)).

### 4.3 Prerequisites
- [LOT-003](./LOT-003.md).

### 4.4 Implementation
1. Implement `CheckpointManager` using `git2` and a separate temporary index (`.git/coloride_tmp_index`) writing exclusively to `refs/coloride/checkpoints/<task_id>/<seq>`.
2. Implement `rollback_to_checkpoint(task_id, seq)` verifying whether the user manually edited any affected file after the agent pass; if so, raise an explicit conflict and never overwrite human edits silently.
3. Implement `CowWorktreeProvisioner` preparing an isolated task worktree in `< 5 ms`.

### 4.5 Mandatory Tests
- **Git Log Non-Pollution & 1-Click Rollback Test (Blocking):** Create checkpoint `C1`, modify 6 files and create 2 new files, then roll back to `C1`; verify `0` checkpoint commits in `git log` and exact restoration.
- **User Edit Protection on Rollback Test (Blocking — Section 5 Blocking Scenario):** After an agent modifies `a.ts` and `b.ts`, manually edit `b.ts` as the user and trigger rollback; verify `a.ts` reverts while `b.ts` preserves the user's changes and reports a conflict.

### 4.6 Acceptance Criteria
- [ ] All checkpoints live under `refs/coloride/checkpoints/<task_id>` with zero impact on `git log` or `.git/index`.
- [ ] Zero user modifications silently overwritten during rollback or worktree reconciliation.

### 4.7 Definition of Done
Invisible Git checkpoint service and CoW worktree provisioner delivered and tested across all 3 OSes.

### 4.8 Risks & Rollback
- **Risk:** External `.git/index.lock` held by a user Git command.
- **Mitigation:** Dedicated temporary index file never contends with `.git/index.lock`.
